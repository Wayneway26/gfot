# AgentSummary

一个本地运行的多 Agent 代码任务协作工作台。依据 [PRD](agentsummary-prd.md) 实现首版手工接力流程。

## 启动

需要 Node.js 22 或以上，无第三方依赖，无需安装依赖或配置 API Key。

```sh
npm start
```

访问 http://127.0.0.1:4317 。关闭终端中的服务后应用停止；再次启动可恢复数据。

其他端口：`PORT=4318 npm start`。服务只监听本机，使用 `127.0.0.1` 访问。

## 使用流程

1. 创建任务，填写真实仓库位置、代码基准、范围和逐项验收条件。
2. 预览、复制或下载实现任务包，交给外部 Agent，并点击“确认已发出”。
3. 把实现结果逐项录入，或导入任务包中约定的 JSON。附实际提交引用或完整 diff，提供明确版本或快照标识；不要仅附对方无法访问的路径。
4. 把审查包交给另一执行端或独立新会话，确认发出，带回审查结果。审查版本需与实现版本完全一致。
5. 有阻断问题则返工，新任务包保留上一轮变更与审查依据。通过后检查交付包，由用户验收或退回。
6. 导出 Markdown 交付说明，继续提交代码或创建 PR。

项目记忆必须附来源与证据版本；需求更新会保留历史快照并将旧结果、审查、记忆标为待复核。实现返回新变更后，既有记忆也保守标为待复核。

## 数据与边界

- 数据存储在 `data/projects.json`，原子替换写入；项目 JSON 可以单独导出。
- 备份与恢复：停止服务后复制或恢复整个 `data/projects.json`，再启动。项目 JSON 导出用于检查和归档，尚不支持将单项目导出直接导入项目列表。
- 删除本地记录不删除仓库或外部会话。删除前可导出备份。
- 不读取仓库、运行 Agent、自动运行测试或探测外部状态；代码版本和证据由用户提供。字段完整不代表内容真实。
- 无云端同步、遥测、外部字体、模型调用或外部账号连接。
- 本机单用户使用，避免同时启动多个服务写入同一个数据目录。不适合暴露到公网。
- 可用 `AGENTSUMMARY_DATA_DIR=/absolute/path` 指定独立数据目录。

## 检查

```sh
npm run check
npm test
```

测试覆盖正常交付、证据缺失、审查版本不一致、审查返工、用户退回、需求变更、旧验收清理、输入快照、阻塞恢复，以及 HTTP 验证、跨源拒绝、服务重启持久化。HTTP 测试会启动临时本地服务并使用独立临时数据目录。

## 首轮真实试用

本版本完成的是可运行的软件闭环；跨外部工具的效率假设还需要真实任务验证。

请在相近难度任务中分别记录原流程与本工具流程的协调用时、材料重写次数、接续追问次数、上下文丢失返工、验收结果和继续使用意愿。不要把功能演示用的测试记录当作真实跨 Agent 成效。

## 审查副本导出

录入实现结果、进入审查阶段后，点击“准备审查副本”：

1. 选择源码文件，或选择项目目录。目录方式保留相对路径；单文件方式使用文件名，同名文件需要分目录选择或重命名。
2. 核对清单、取消不需要的文件，并查看排除原因。只读取勾选文件的内容；被排除项仅用于显示名称与原因。
3. 确认所选文件对应当前交付版本。这个对应关系由用户确认，产品不会自动把仓库状态当作已验证事实。
4. 生成预览，检查任务内容、完整源码和每份文件的 SHA256，再下载单个 Markdown 副本。
5. 实际交给外部 Agent 后，再确认任务已发出。下载不会自动派发、改变状态或验收。

副本包含目标、验收条件、实现阶段提供的差异或变更引用、验证说明，以及本次选中的文本快照。导出服务只接收显式文本，不按仓库路径读取文件，也不把上传内容保存到项目数据。若差异只是本地文件引用，需另行选入实际 diff 文件，否则接收方未必能比较修改前后。

默认排除 data/、隐藏目录、依赖、构建产物、历史 trials/，以及常见凭证文件名；拒绝路径跳转、重复路径、无效 UTF-8、二进制及过大文件。最多 80 份文件，单份 300 KB，总计 1 MB。筛选不是秘密扫描，合法文件名下仍可能含敏感内容，发送前需人工核对。

**这是材料隔离，不是权限沙箱。** 它不会撤销 WorkBuddy 等外部 Agent 已有的系统访问权。不要在仍有广泛本地权限的 Agent 中无监督执行副本代码。本次 macOS 命令沙箱探针未能正常启动，未提供无约束回退；已提供下方独立容器检查器，限制它启动的命令；它不限制 WorkBuddy 桌面进程。

## 受控命令检查器

使用 Docker 本机服务，将导出的 Markdown 副本还原为经过 SHA256 校验的临时文本目录，再在容器中运行检查：

```sh
node scripts/isolated-check.mjs trials/isolation-002/review-copy.md
```

检查器只允许本机 Unix-socket Docker 服务。镜像固定为官方 Node 22 Alpine 的内容摘要，不自动下载、不执行依赖安装。若本机没有该镜像，先明确拉取：

```sh
docker pull node@sha256:0a7108bf6c7bf5de370ffb1a3ed6be93d405b43ff159f681a8d18c0e2bc2e402
```

每次运行使用随机临时副本和容器名，仅只读挂载 `/review`，不挂载真实仓库或 Docker socket；禁止外网，根文件系统只读，丢弃全部 capabilities，禁止提权，以非 root 用户运行，并限制 CPU、内存、进程数、输出量和执行时间。只允许 `/tmp` 临时写入。结束或失败后清理本次容器与临时目录，不清理用户其他容器。

依次验证边界、运行副本内的 `npm run check` 与 `npm test`。镜像、解析、校验、Docker 或测试任一步失败，均停止，**不会回退到宿主机执行源码**。快照里的脚本仍是不可信输入，限制针对容器内命令生效；无法约束另一个已经拥有本机访问权的桌面 Agent。

本轮验证：最新宿主源码 24 项测试通过；从界面导出的 v1 副本内 21 项测试在容器通过，并实测宿主数据不可读、副本不可改、外网不可达。v1 副本与后续新增检查器属于不同快照，历史副本不会被静默覆盖。

最终完整 v2 副本也已验证，可运行：

```sh
node scripts/isolated-check.mjs trials/isolation-002/review-copy-v2.md
```

该副本包含 15 个文件，容器内 24/24 测试通过；完整输出见 `trials/isolation-002/container-check-v2.log`。
