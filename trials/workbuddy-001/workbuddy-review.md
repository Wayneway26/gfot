## 四、发现

**阻断问题：无。**

**非阻断建议：**

1. 新增测试依赖 `setTimeout(30ms)` 把写入拆成多次，依赖操作系统的 TCP 缓冲与 Nagle 时序，属于时序敏感测试。本次连跑 5 次均通过，但慢速 CI 或高负载环境下理论上存在偶发风险。需要说明：该请求未设置 `Content-Length`，Node 通常已自动改用 `Transfer-Encoding: chunked`，因此「显式声明 chunked」本身并不构成消除时序依赖的保证，只能作为方向之一；若要提高确定性，应改为由测试自身精确控制写入边界。执行端已在 `issues` 中主动披露时序敏感性，判断恰当。
2. `Buffer.concat` 对 2 MB 以内的请求体做一次额外拷贝。相对文件 IO 可忽略，不建议为此改动；若未来有大量并发大请求，可评估复用缓冲区。
3. `manifest.json` 仅覆盖 `server.mjs` 与 `test/server.test.mjs`，未包含 `domain.mjs`、`public/app.js`。本次已确认二者未被本次改动触及，但建议后续将全部在范围内的文件纳入哈希清单，使版本快照的完整性可机械校验。

**未验证事项（明确声明）：**

- 仅在 macOS / Node v22.22.2 下运行，未在其他操作系统与 Node 版本验证。
- 未做性能压测，分块修复对吞吐与内存的实际影响未量化。
- 未构造任意损坏的 UTF-8 字节流（如非法字节序列、BOM、`surrogate` 转义）验证健壮性；`toString('utf8')` 对非法输入会静默产生 `U+FFFD`，此为 Node 标准行为，未在本次范围内。
- 未运行工作台 API，未填写工作台字段（按审查约束，本报告需人工导入）。
- 未验证 `delivery()` 交付包路径下的标题渲染（该路径要求项目先处于 delivery 阶段并有通过的审查记录，本次以 `taskPack` 交接包为准验证）。
- **审查过程自身的范围偏离（如实记录）**：审查收尾阶段，我曾对未在授权范围内的 `data/projects.json` 执行 grep/stat 污染排查，该操作被协调者叫停并判定违反文件范围限制。相关 mtime 的成因按协调者说明归于工作台记录派发，我未继续调查，也未据此形成任何结论。此处如实登记，供后续审计核对；本次审查的技术结论不依赖该次操作。
