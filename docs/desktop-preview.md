# gfot macOS 预览版（0.4.0）

更新时间：2026-10-20。

## 当前产品

自己的 macOS GUI → 本地任务服务 → 内置 OpenCode Agent Loop → 用户配置的 HTTPS 兼容 API 或本机模型服务 → 上游 / 本机模型。

同一个本地项目、同一个任务和 OpenCode 会话，可以在回合之间选择不同模型连接。模型改变，执行器保持不变。这与切换到 WorkBuddy / Codex 的完整 Agent 执行器不同。

## 可用范围

- 原生目录选择、持久化任务和对话、执行事件与工具批准。
- HTTPS API 直连和本机服务连接管理；模型列表读取与需确认的推理 / 工具回传检查。
- 模型连接管理，访问密钥由 macOS 钥匙串保护的主密钥加密。
- 修改文件、运行命令与访问项目外目录需批准。权限提示不是操作系统沙箱。
- 停止或退出时清理执行进程；本地服务异常消失时，监督进程清理执行进程组。重启时将未完成任务标为中断，用户应核对文件再继续。
- Apple silicon 的 unsigned ZIP 和 .app；尚未签名、公证，也未验证 Intel Mac。

## 尚未接入

Codex 本地凭证导入和独立 ChatGPT 授权现为实验功能，详见 [账号文档](accounts.md)。仅本地导入账号提供手动兼容额度查询，其他平台凭证导入及自动切换未实现。WorkBuddy 完整执行器、Codex 完整执行器和 Harness² 递归改进均不在本次桌面版中。不能把“代理可达”当成“某家订阅可用”。

## 验收证据

自动测试以本机合成模型驱动真实 OpenCode，验证批准后写入临时文件、工具结果回传、关闭服务再打开后保留会话并切换模型。原生 Electron 界面测试检查渲染隔离、目录选择桥接、连接编辑不改变选择，以及同一会话的两轮模型执行。一个真实 Codex 导入账号已通过模型目录、推理与工具回传诊断；独立浏览器授权与其他兼容性仍需验证。

## 与旧工作台的关系

原 gfot-prd.md 描述的是旧版“多 Agent 手工交接 / 独立审查”工作台，仍可通过 npm start 运行。它与桌面预览版的数据目录和任务不同，不会自动迁移。当前桌面产品范围以本文和 README.md 为准。

## Harness²

本版本没有在任何运行路径中调用 Harness²。现有执行器为 OpenCode。README 的架构章节列出了未来外层递归改进模式的接入位置与尚缺的隔离探测、预算和采用确认。
