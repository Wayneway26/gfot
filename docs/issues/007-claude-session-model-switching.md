# 在同一 Claude 任务中切换账号和模型并继续执行

状态：待实现；本地 Issue，尚未发布到 GitHub。
优先级：P1。
阻塞依赖：本地 Issue 005「让 gfot 中的 Claude Code 使用 Codex 账号调用 GPT」。兼容 API 连接随 006 完成后纳入，不阻塞本条首轮验收。
基线：h2 / 26e51fd。

## 要解决的问题

接通一次 Claude 执行与一次跨模型调用，还不能保证账号额度耗尽后可靠续接。用户需要保留 gfot 中的项目、任务、共享记忆与 Claude 原生会话，并在切换后核对已有工具操作，继续剩余工作。

## 交付行为

用户在任务空闲时主动换账号或模型；遇到可识别的额度错误时，点击“切换连接并继续”，选择另一个已验证的连接，仍在原任务中完成工作。用户也能在 dsh 与 Claude 执行器之间交接，界面明确区分原生会话恢复和可见上下文交接。

## 验收标准

- [ ] 同一 Claude 任务可在两个支持的账号/模型连接间切换，保留任务 ID、项目目录、对话、共享备注与原生 Claude 会话 ID；真正不可恢复时明确报错，不静默伪造恢复成功。
- [ ] 切换前验证目标凭证和基础配置；目标已退出、过期且不可刷新或缺少密钥时，不中断原任务去尝试不可用连接。
- [ ] 任务执行中先请求中断、取消待处理审批，保存公开进度与工具证据，确认旧执行结束后再启用新路由。结束状态未知时阻止续接。
- [ ] 429/额度不足可触发明确的切换入口；普通服务错误不被随意认定为余额为零。支持用户主动切换，不自动轮询其他账号或重复付费诊断。
- [ ] 有过写文件等操作的失败回合不会被自动原样重放。续接携带已完成/未完成/未知状态，要求执行器核对当前文件后继续。
- [ ] 主任务和子 Agent 的模型角色在下一次启动时使用新映射；原生子任务或后台命令仍运行时，不能仅修改界面选择就称为全部切换完成。
- [ ] 不兼容的上下文容量、历史内容或能力变化需要明确处理；不能静默删除用户输入或内部工具结果来假装无缝续接。
- [ ] 重开 gfot 后保留选择的执行器、账号连接、原生会话与交接记录；运行中崩溃不自动重放。
- [ ] dsh 与 Claude 互相交接时，共享项目约定、任务备注、近期可见对话、工具证据和已经采用的 Harness² 指令；不复制对方私有思考、不把不同引擎的会话 ID 混用。
- [ ] 用真实 Claude 运行时和合成双账号验证“账号 A 批准并完成文件写入 → 模拟限额 → 切换 B → 同会话续接 → 重启恢复”，确认没有重复写入或失去既有上下文。
- [ ] 打包版 UI 验证主动切换、额度错误后的续接、拒绝停止与无效目标四条路径。

## 范围

本条提供用户确认的续接，不引入无人确认的自动故障切换。Harness² 的现有采用结果应能传递，但不在本条增加 Claude 驱动的全套副本探测或递归优化。
